2. ChatGPT + connected Drive editor

With the user's permission the connected Google Drive/Sheets tools can directly read cells, inspect formulas, reorganize tabs, move files, maintain versioned PRE/POST copies and append audit Docs. This interactive access is different from GitHub Actions' cloud identity; a chat being able to read a Sheet does not itself give a GitHub runner permission.

3. Existing Google Cloud Workload Identity

Google Cloud project just-a-project-5007 already provides keyless GitHub federation to jp-pages-publisher. The runner obtains a short-lived scoped Google token and must have Viewer permission on each private source workbook. Vendor and Contractor LIVE readers now reuse these grants; no new account or source-ID secret is mandatory when an exact unique title is discoverable.

4. GitHub — versioned source and QA

FabinGurung/jp-estimating-and-boq owns finance source adapters, public-safe source map data/connected-website-sheets.v1.json, per-source aggregate contracts, application pages and CI tests. The publishing branch is research/open-estimation-engine-v0.1. A7 is a navigation and governance pointer, not a duplicate financial ledger.

Manual update procedure — what to ask next time

  1. Edit the existing owner-designated LIVE Sheet; never create a second editable authority or overwrite source evidence.
  2. Preserve a numbered A7 PRE → edit → inspect/reconcile → POST history; maintain stable file ID and explicit approval status.
  3. Request an authenticated, one-off refresh via Cost Estimation manual Pages refresh. For Amrit rate assumptions only, use the manual Amrit source sync.
  4. For Vendor Bills, the repository's JP_VENDOR_BILLS_SHEET_ID source setting and the publishing identity's read access must be verified before a separately requested manual research Pages refresh. Push deployment is only a verified snapshot.
  5. Check the exact Actions run log, public-safe output, publication commit and live Pages rendering. A successful old run is not evidence of today's refresh.
